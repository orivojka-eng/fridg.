# FRIDGR — Deployment runbook (zero budget)

Everything here is free except the Apple Developer Program. Never paste secret values into chat, code or docs: they go only into `server/.env` (local) or the Render dashboard (production).

| Piece | Service | Free limit that matters |
|---|---|---|
| API + public pages (privacy, terms, support, password reset) | Render free web service | Sleeps after 15 min idle; ~30–60 s cold start; outbound SMTP blocked |
| Database | Neon free | 0.5 GB; compute auto-suspends when idle |
| Email | Brevo (300/day) or Resend (3,000/month, needs a domain) | via HTTPS API, not SMTP |
| AI | Gemini API free tier | per-minute limits; the app caps free users per day |
| App builds | Expo EAS free | queued builds |

## 0. Local development

```bash
cd server
cp .env.example .env            # fill DATABASE_URL, DIRECT_URL, BETTER_AUTH_SECRET, GEMINI_API_KEY
npm install
npm run db:migrate              # applies committed migrations only, never resets data
npm run dev                     # API on http://0.0.0.0:$PORT
```

- Phone on the same Wi-Fi: set `BETTER_AUTH_URL=http://<PC LAN IP>:<PORT>` in `server/.env`, and `EXPO_PUBLIC_API_URL` to the same in the app `.env`.
- No email provider + `APP_ENV=development` → emails (with codes/links) are printed in the API log. In any other `APP_ENV` they are never logged and sending fails loudly.
- Offline database: `npm run db:dev` starts an embedded Postgres on port 5499 (use it to test new migrations before Neon).

## 1. Database (Neon)

1. console.neon.tech → project → **Connection Details**.
2. **Pooled** connection string (host contains `-pooler`) → `DATABASE_URL`; add `&pgbouncer=true` if missing.
3. **Direct** connection string (no `-pooler`) → `DIRECT_URL` (used only by `prisma migrate deploy`).
4. Migrations already applied on Neon: `0001_init`, `0002_support_tickets`, `0003_external_recipes`, `0004_better_auth`. The work in this release added **no** new migration.
5. Schema changes later: edit `server/prisma/schema.prisma` → `npm run db:migrate:dev -- --name <change>` against the local embedded DB (`npm run db:dev`) → review the SQL → commit the folder → Render applies it on the next deploy with `migrate deploy`.
6. Safety: Neon → **Branches** → create a branch before any risky migration (instant copy, free). Never run `prisma migrate reset` or `db push --accept-data-loss` against Neon.

## 2. API on Render

1. Push this repository to GitHub (private repo is fine). `.gitignore` already excludes `.env`, `node_modules`, builds.
2. render.com → **New → Blueprint** → select the repo. `render.yaml` creates `fridgr-api` (Node 22, free plan, Frankfurt).
3. Fill every variable marked "sync: false" (dashboard → fridgr-api → **Environment**):

   | Variable | Value |
   |---|---|
   | `BETTER_AUTH_URL` | `https://<service>.onrender.com` (shown at the top of the service page). Must be https. |
   | `DATABASE_URL`, `DIRECT_URL` | from Neon (step 1) |
   | `GEMINI_API_KEY` | from aistudio.google.com |
   | `BREVO_API_KEY` **or** `RESEND_API_KEY` | from the email provider (section 3) |
   | `EMAIL_FROM` | `FRIDGR <the-verified-sender@address>` |
   | `SUPPORT_INBOX` | address that receives support tickets |
   | `GOOGLE_CLIENT_ID_IOS` | from Google Cloud (section 4) — optional until Google sign-in is wanted |
   | `APPLE_TEAM_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY` | from Apple Developer (section 5) |
   | `EXPO_ACCESS_TOKEN` | expo.dev → Access tokens (optional) |
   | `REVENUECAT_SECRET_API_KEY` | RevenueCat → API keys → secret key (section 6) |

   `BETTER_AUTH_SECRET` and `REVENUECAT_WEBHOOK_SECRET` are generated by Render. Keep `BETTER_AUTH_SECRET` stable: changing it signs everyone out and makes stored Apple tokens unreadable.
4. Deploy. Build: `npm ci --include=dev && npx prisma generate && npm run build`. Start: `npx prisma migrate deploy && node dist/index.js`.
5. Check:
   - `GET /health` → `{"status":"ok","db":"ok","email":"live"}`. `email:"NOT_CONFIGURED"` means no provider key is set.
   - `GET /health/ip` from your phone (mobile data) → must show your phone's public IP. If it shows a Render/Cloudflare address, set `TRUST_PROXY_HOPS=2` and redeploy (rate limits depend on this).
   - Logs → one "service status" line lists which services are live (names only).
6. Keep it warm (optional, free): cron-job.org → new job → `https://<service>.onrender.com/health/live` every 10 minutes. `/health/live` does not touch the database, so Neon can still sleep.

The production server refuses to start when `BETTER_AUTH_URL` is not https or points to localhost/a LAN IP, so email links can never contain a development address.

## 3. Email

Pick one. Both are HTTPS APIs (Render blocks SMTP).

**Brevo (no domain needed)**
1. brevo.com → sign up (free plan).
2. **Senders, Domains & Dedicated IPs → Senders → Add a sender** → the address emails should come from (e.g. the app's Gmail) → confirm the link Brevo emails you.
3. **SMTP & API → API Keys → Generate a new API key** → copy once → Render `BREVO_API_KEY`.
4. `EMAIL_FROM=FRIDGR <that verified address>`.
   Note: mail from a free address (gmail.com) is more likely to land in spam; a domain later fixes that.

**Resend (needs a domain you own)**
1. resend.com → sign up → **Domains → Add domain** → add the DNS records it shows → wait for "Verified".
2. **API Keys → Create** (permission "Sending access") → Render `RESEND_API_KEY`.
3. `EMAIL_FROM=FRIDGR <hello@your-domain>`.
   Without a verified domain Resend only delivers to your own account address.

After setting the key: sign up in the app with a real mailbox you control and confirm the code arrives (inbox and spam folder).

## 4. Google sign-in (iOS)

1. console.cloud.google.com → create project "FRIDGR".
2. **APIs & Services → OAuth consent screen** → External → app name FRIDGR, support email, privacy policy URL `https://<service>.onrender.com/legal/privacy` → scopes `openid`, `email`, `profile` → **Publish app** (to production) so any Google user can sign in.
3. **Credentials → Create credentials → OAuth client ID → Application type: iOS** → Bundle ID `com.fridgr.app` → Create. Copy the **Client ID** (`…apps.googleusercontent.com`). iOS clients have no secret.
4. The redirect URI is fixed by Google for iOS clients: `com.googleusercontent.apps.<id-prefix>:/oauthredirect` (the reversed client id). Nothing to type: `app.config.js` registers that URL scheme in the iOS build automatically.
5. Paste the client id in two places:
   - Render → `GOOGLE_CLIENT_ID_IOS` (server checks the token's audience).
   - EAS → `eas env:create --name EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID --value <client id> --environment production --environment preview --environment development --visibility plaintext` (public value, compiled into the app).
6. Rebuild the app (a new native build is needed because the URL scheme changes). Google sign-in does not work in Expo Go.

Android is not configured (Play Console account costs money; Android also needs an Android OAuth client + SHA-1).

## 5. Sign in with Apple

Code is complete: the app uses the native Apple sheet, the server verifies Apple's identity token (audience = bundle id), stores Apple's refresh token encrypted, and revokes it when the account is deleted.

1. developer.apple.com → **Certificates, IDs & Profiles → Identifiers** → App ID `com.fridgr.app` → tick **Sign in with Apple** (and **Push Notifications**) → Save.
2. **Keys → +** → name "FRIDGR Sign in with Apple" → tick **Sign in with Apple** → Configure → primary App ID `com.fridgr.app` → Continue → Register → **Download** the `.p8` (only once).
3. Render: `APPLE_KEY_ID` (Key ID shown on the key page), `APPLE_TEAM_ID` (Membership page), `APPLE_PRIVATE_KEY` = full `.p8` text (newlines may be written as `\n`).
4. Without these three, sign-in still works; only the token revocation on deletion is skipped (logged).

## 6. RevenueCat (subscriptions)

1. App Store Connect → the FRIDGR app → **Subscriptions** → group "Premium" → `fridgr_premium_monthly`, `fridgr_premium_yearly` (7-day free trial each). Paid Applications Agreement must be Active.
2. app.revenuecat.com → project FRIDGR → **Apps → + App Store app** → bundle `com.fridgr.app` → upload the App Store Connect in-app purchase key (.p8) as RevenueCat asks.
3. **Products** → import both. **Entitlements → + `premium`** → attach both. **Offerings → `default`** → monthly + annual packages.
4. **Integrations → Webhooks → +** → URL `https://<service>.onrender.com/v1/subscriptions/webhook` → Authorization header `Bearer <REVENUECAT_WEBHOOK_SECRET>` (copy the value Render generated).
5. **API keys**: the public Apple key → EAS `EXPO_PUBLIC_REVENUECAT_IOS_KEY`; the **secret** key → Render `REVENUECAT_SECRET_API_KEY` (never in the app). With the secret key the server confirms purchases directly with RevenueCat; without it Premium only switches on through the webhook.

## 7. iPhone app (EAS)

```bash
npm install -g eas-cli
eas login
eas init                                   # links the project to your Expo account (once)
eas env:create --name EXPO_PUBLIC_REVENUECAT_IOS_KEY --value <public key> --environment production --visibility plaintext
eas build --profile development --platform ios   # dev client for your iPhone (needs Apple account)
eas build --profile production --platform ios
eas submit --profile production --platform ios   # fill ascAppId + appleTeamId in eas.json first
```

`EXPO_PUBLIC_USE_BACKEND=true` and `EXPO_PUBLIC_API_URL=https://fridgr-api.onrender.com` are set per profile in `eas.json`. If Render gives the service a different URL, change it there. Release builds log an error if the API URL is not https or is a LAN address.

The app copes with Render's cold start: reads retry for up to ~75 s, writes wake the server first, and the user sees "The FRIDGR server is waking up" instead of a generic error. A saved session is only removed when the server answers 401, never because the phone was offline.

## 8. Verification after every change

```bash
cd server && npm run typecheck && npm run build
cd .. && npx tsc --noEmit -p . && CI=1 npx expo export --platform web
```

Smoke test on the deployed API: sign up with a real mailbox → code arrives → verify → sign out/in → Forgot password → link opens the https reset page → new password works → Profile → Delete account (test account only).
